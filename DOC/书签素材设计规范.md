# 书签素材设计规范

- 版本：v1（2026-11-14）
- 适用：阅读页侧边书签入口（`BookmarkEntry` / `BookmarkEntryArtwork`）的全部素材
- 关联：[M1-014 爪/头两态](./TODO/M1-014-书签入口爪头两态.md)、[M1-014 Guide](./Guide/2026-11-14-M1-014-书签入口爪头两态.md)、[feature-reader 模块](./Module/feature-reader.md)
- 目标：设计者只按本文出图，不改代码就能替换入口素材，且比例、方向、三态偏移、边缘裁切全部符合预期。

一句话原则：**素材只画一张、保持原始比例、正立绘制；三态由代码整体平移实现，不缩放、不裁切、不做非等比拉伸。**

## 1. 锚点与方向

### 1.1 入口锚在哪条边

| 朝向 | 锚边 | 说明 |
| --- | --- | --- |
| 竖屏 | 屏幕**右**长边 | 入口为竖向条，贴右边，初始贴右上角 |
| 横屏 | 屏幕**右**短边 | 同样是当前朝向的右边缘，转屏后自动重贴 |
| 左侧（预留） | 屏幕**左**边 | 配置 `entrySide = left` 时启用，规则镜像，不出新图 |

入口可视矩形固定为 **40 dp（厚，垂直边）× 132 dp（长，沿边）**，贴边一侧为直角，靠屏幕内侧两角圆角 12 dp。

### 1.2 素材的「上」朝哪

- 书签的「上」= 所贴边的**外法线方向**（远离屏幕中心、朝屏幕外）。
- 贴右边时素材顶端朝**屏幕右**；贴左边时朝**屏幕左**。同一张图不用镜像、不用重画。
- 实现方式：`RotatedBox(quarterTurns: 0 → 贴右 1 / 贴左 3)`，顺时针 90° 让源图上方转向屏幕右侧。

| 贴边 | `entryQuarterTurns` | 源图「上方」最终朝向 | 源图「下方」（爪）最终朝向 |
| --- | --- | --- | --- |
| 右侧（默认） | 1（顺时针 90°） | 屏幕右 = 外侧 | 屏幕左 = 内侧 |
| 左侧（预留） | 3（逆时针 90°） | 屏幕左 = 外侧 | 屏幕右 = 内侧 |

**出图要求：按「正立」画——头在上、爪（或底部）在下。** 不要为了贴边把图画成横的，旋转由代码完成。

### 1.3 「外法线」在本实现里指什么

- 屏幕语义：贴右边时外法线 = 屏幕 **+x**（向右）；贴左边时 = 屏幕 **−x**。
- 代码语义：素材在旋转前的自身坐标系里统一换算成 **本地 −y**（向上）。
  因为 90° 旋转把本地 −y 映射到屏幕右侧，所以「推出屏幕」对左/右两种贴边都只是同一个标量位移，不需要分支。
- 位移量 `outwardOffset` 直接作用在 `Transform.translate(offset: Offset(0, -outwardOffset))`，单位 dp。

### 1.4 示意图（贴右边，竖屏）

```
                        屏幕右边缘
                             │
 idle（静止）                 │
   ┌───────────────────┐     │
   │      透明留白      │     │   头被推到屏幕外
   │  ┌─────────────┐  │     │
   │  │  爪（露 11.2）│──┼─────┤   ← 屏内只剩爪部一截
   │  └─────────────┘  │     │
   └───────────────────┘     │
                             │
 active（面板打开）           │
   ┌───────────────────┐     │
   │  ┌─────────────┐  │     │
   │  │     头       │  │     │   位移归零
   │  │     爪       │  │     │   整图回到入口内
   │  └─────────────┘  │     │
   └───────────────────┘     │
```

（图示为示意，实际素材可比入口条窄。）

## 2. 三态位移表

基准是**入口可视矩形**（40 × 132 dp，贴右边）。位移只沿外法线，只有一个标量。

| 状态 | 触发 | 位移方向 | 位移量 | 相对基准 |
| --- | --- | --- | --- | --- |
| idle（静止） | 初始 / 面板关闭 | 向外 | **28.8 dp** = `40 × 0.72` | 屏内只剩素材底部 11.2 dp（28%） |
| dragging（拖拽） | 按住并移动超过 `kTouchSlop` | 向外 | **30.8 dp** = 28.8 + `pullOffset 2` | 在静止值上再外移 2 dp，始终不露头 |
| active（激活） | 面板打开 | — | **0 dp** | 整图回到入口内，头部露出 |

- 过渡：`headReveal` 由独立 `AnimationController` 驱动，**280 ms / `Curves.easeOutBack`**（收尾超调形成轻微回弹，约 3 dp，属预期）。
- 三态阴影/位移的小参数由 `entryStateTransitionDuration`（180 ms / `easeOutCubic`）插值，避免瞬变。
- **明确禁止**：状态驱动的缩放（旧版 1.08 / 1.03 已删除）、旋转、非等比拉伸、`ClipRect` 裁图分层。三态差异只允许是位移（+ 可选阴影）。
- 允许浮动范围：
  - 静止推出比例 `entryStaticOutwardRatio` 建议 **0.60–0.85**；小于 0.6 会露头/露身，大于 0.85 爪部只剩一条细边（<6 dp）不好点认。
  - 拖拽额外位移 `pullOffset` 建议 **0–4 dp**，只为「活着」的手感，不得形成挤压或拉伸。
  - 相对位移量变化时，素材本身无需重画；但**爪部占画布高度的比例要跟着调**（见 §3.5）。

热区与视觉解耦：可点击/可拖动区域恒为 **40 × 132 dp**，不随素材实际渲染尺寸变化；素材画得小不会点不中。

## 3. 绘制尺寸与素材规格

### 3.1 显示盒

- 旋转前（素材自身坐标系）：**132 dp 宽 × 40 dp 高**。
- 旋转后（屏幕坐标系）：**40 dp 宽 × 132 dp 高**，贴当前朝向右边缘。

### 3.2 `BoxFit.contain` 的换算

`Image.asset(width: 132, height: 40, fit: BoxFit.contain)`，即：

```
scale = min(132 / 源图宽, 40 / 源图高)     // 取较小值，任一方向都装得下
渲染宽 = 源图宽 × scale
渲染高 = 源图高 × scale
```

宽高比始终等于源图，**不做非等比拉伸**。由于 132 / 40 = 3.3：

- 宽高比 **≤ 3.3 : 1** 的素材，**高度方向顶满 40 dp**（爪的露出比例稳定），宽度按比例；
- 宽高比 **> 3.3 : 1** 的素材，宽度顶满 132 dp，高度会不足 40 dp，厚度方向出现透明留白，**不推荐**。

常用比例换算示例（旋转前坐标）：

| 源图宽高比 | 渲染尺寸（dp） | 说明 |
| --- | --- | --- |
| 1 : 1（当前 `cat-icon@3x.png` 96×96） | **40 × 40** | 推荐，当前实现 |
| 4 : 3 | 53.3 × 40 | 可接受 |
| 3 : 2 | 60 × 40 | 可接受 |
| 16 : 9 | 71.1 × 40 | 可接受，竖向占比小 |
| 3.3 : 1 | 132 × 40 | 正好铺满整条入口 |
| 4 : 1 | 132 × 33 | 不推荐（厚度留白，爪露出比例会变） |
| 1 : 2（竖版） | 20 × 40 | 不推荐（渲染过窄） |

> 注意：方形素材渲染只有 40 dp 见方，入口条长 132 dp，因此竖向两端会留出空白，属于预期效果。想让素材视觉上填满整条入口，就按 **3.3 : 1** 出（如 396 × 120 px）。

### 3.3 源图像素与 dpr

- dp → px 按设备像素比换算；常见 dpr：Android xxhdpi ≈ 3.0、Pixel 5 模拟器 2.75、桌面 1.0–2.0。
- 入口最大渲染边长 **40 dp**，按 3x 资源标准需要 **120 px**；建议再留插值余量。
- 推荐规格：

| 项目 | 建议 |
| --- | --- |
| 最小像素 | **120 × 120 px**（1:1，对应 40 dp @3x） |
| 推荐像素 | **240 × 240 px**（覆盖 4x–6x，缩放不糊） |
| 格式 | PNG，带 alpha |
| 命名 | `assets/images/bookmark/<name>@3x.png`，与现有 `cat-icon@3x.png` 一致 |
| 引用位置 | `ReaderUiConfig.entryAssetPath`（换图只改这一处常量） |

> 现状核对：`cat-icon@3x.png` 实际为 **96 × 96 px**，即 2.4x；显示仍正确，但若换图建议提升到 120–240 px。

### 3.4 宽高比要求

- 必须与源图一致，代码不做任何拉伸；**出图时不要为了「填满竖条」把方形图压成竖长条**。
- 推荐 **1 : 1 ± 15%**（0.85–1.15）。比例越偏离 1:1，厚度方向留白或占比变化越明显。
- 构图居中：`contain` 会把**整张画布**等比缩放并居中放进 132 × 40；不要在画布里做「偏心排版」来对齐（例如把猫塞到画布右下角去贴边），否则留白会被一起缩放，位置对不上。

### 3.5 爪部与头部的构图比例

因为静止态只露出素材底部（旋转前坐标的下方）**11.2 dp（画布高度的 28%）**：

- **爪部应占据画布高度底部约 25%–30%**（1:1 画布下约 11 dp 高），静止时正好只看得到爪。
- **头部位于画布上方**；头顶留 2–4 dp（约 5%–10%）安全边，避免 `easeOutBack` 超调时视觉上贴边发紧。
- 头与爪之间不要出现「头一露就整只都出来」的断层——中间是身体，激活态整图可见，构图要完整。

### 3.6 透明边距

- 底色必须完全透明（alpha = 0），不要白底/深色底/棋盘格，否则入口条会变成一块卡片。
- **四周裁掉多余透明边**（保留 0–2% bleed 即可）：`contain` 会把透明像素算进缩放，透明边越大，实际看到的图越小。
- 不要用透明边去「模拟位移」或「预留出屏空间」，位移由代码完成。

## 4. 视觉细节

| 项目 | 规范 |
| --- | --- |
| 圆角 | 入口形状：贴边一侧直角，靠屏幕内侧两角 **12 dp** 圆角（`entryCornerRadius`），由代码 `ClipRRect` 施加，属入口容器而非素材 |
| 素材自带圆角 | 不需要。素材轮廓就是最终轮廓，圆角只作用于入口矩形边界 |
| 阴影 | **由代码加**：`BoxShadow` 画在入口矩形上，idle 无阴影、dragging（blur 16 / 0.22 / 偏移 −6,0）、active（blur 12 / 0.16 / 偏移 −4,0）。素材**不要自带投影、外发光或落地阴影**，否则会叠加成双层脏边 |
| 背景透明度 | 素材全透明背景；入口除素材外不铺任何底色（仅资源加载失败时用深色圆角占位 `0xE62E2E2E`） |
| 描边 | 建议 0–2 px 内描边或浅色外发光之外不加；深色描边在浅色页面上会更「贴纸感」，按视觉稿定 |
| 系统状态栏 | 阅读页为沉浸式（隐藏状态栏与导航栏），素材**不需要**为状态栏留安全边 |
| 系统返回手势区 | 入口在 Android 上会注册手势排除矩形（每边 200 dp 预算内），素材不需要额外内缩；但**爪部不要贴着屏幕边缘画得过细**，<6 dp 的可见宽度虽可点，视觉上难辨认 |
| 与面板的关系 | 面板从入口同侧滑入，右边缘让出 40 dp（`panelSideOffset`），入口始终可见、不被遮罩压暗；素材不需要考虑被面板遮挡 |

## 5. 分层可选方案（爪 / 头分开）

当前只有一张整图，靠整体位移实现两态。将来若要「爪一直扒着、头单独探出」，按下面拆即可，**不改交互与状态机**：

### 5.1 拆法

| 图层 | 文件 | 内容 | 绘制顺序 |
| --- | --- | --- | --- |
| 爪层（底） | `assets/images/bookmark/cat-paw@3x.png` | 只含爪子/贴边部分，**不含头** | 下 |
| 头层（上） | `assets/images/bookmark/cat-head@3x.png` | 只含头部（可与身体断开） | 上 |

### 5.2 对齐与导出约定

1. **两张图使用完全相同的画布尺寸**（如都是 240 × 240 px），且在画布内保持与整图时相同的位置。
2. 直接叠加即对齐（同一原点、同一缩放），**不要在导出时各自裁剪再靠数值偏移对齐**。
3. 头层默认与爪层共用同一个 `headReveal` 位移；需要「头单独探出更多」时，头层可叠加额外位移或透明度，但两者都必须保持等比。
4. 若两图比例不同，只改各自的绘制尺寸配置，不改变叠加顺序与共用进度。

### 5.3 代码接入点

`BookmarkEntryArtwork` 由「一张图」改为「两层 `Stack`」：

```dart
Stack(
  clipBehavior: Clip.none,
  children: <Widget>[
    Transform.translate(offset: Offset(0, -pawOffset),  child: 爪层),
    Transform.translate(offset: Offset(0, -headOffset), child: 头层),
  ],
)
```

`headReveal`、`pullOffset`、位移比例、时长曲线、三态、吸附与面板逻辑全部复用。

## 6. 验收清单（设计者自查）

出图后逐条打勾：

- [ ] **比例不变形**：源图宽高比与预期一致，未被压扁/拉长；按 1:1（或设计定好的比例）导出。
- [ ] **背景透明**：无白底/深色底，四周多余透明边已裁掉。
- [ ] **方向朝外**：按正立绘制（头在上、爪在下）；代码旋转后头朝屏幕外侧、爪朝内侧。
- [ ] **爪部比例正确**：爪部占画布高度约 25%–30%，静止时屏内只看得到爪。
- [ ] **三态偏移合理**：静止推出 28.8 dp（露 11.2 dp）、拖拽 +2 dp、激活 0；切换时无缩放/倾斜。
- [ ] **边缘不被裁**：头与爪的关键轮廓完整，头顶留 2–4 dp 安全边；没有元素被入口 12 dp 圆角切掉。
- [ ] **无自带阴影**：素材不带投影/外发光，避免与代码阴影叠加。
- [ ] **命名与路径**：`assets/images/bookmark/<name>@3x.png`，并在 `pubspec.yaml` 声明、同步 `ReaderUiConfig.entryAssetPath`。
- [ ] **深浅底都能看**：在白色阅读底与深色遮罩下均可辨认（彩色图不染色）。

## 7. 常见错误示例

| 错误 | 现象 | 正确做法 |
| --- | --- | --- |
| 把方形图压成 40 × 132 填满竖条 | 猫被纵向拉长（旧版 `BoxFit.fill` 的问题），严重变形 | 保持原始比例，交给 `BoxFit.contain`；想填满就按 3.3:1 出图 |
| 为了让头朝外，自己在图里把猫旋转 90° | 代码再转 90°，头转回内侧了（转反） | 正立出图，旋转由 `entryQuarterTurns` 完成 |
| 素材自带投影/外发光 | 叠上代码阴影后出现双影、脏边 | 素材不带阴影，阴影只在三态里由代码加 |
| 白底/深底不透明 | 入口条变成一块方形卡片，遮住页面 | 透明背景，只保留主体轮廓 |
| 四周留大量透明边 | 实际看到的图比预期小一圈，爪也变小 | 裁掉多余透明边，只留 0–2% bleed |
| 在画布内偏心排版来「贴边」 | `contain` 把整块画布居中缩放，位置全偏 | 图在画布内居中，边缘对齐靠代码的贴边布局 |
| 爪只占画布底部 10% | 静止时几乎看不到爪，只剩一条边 | 爪部占底部 25%–30% |
| 用缩放/挤压表达拖拽 | 拖动时图变胖/变瘦 | 拖拽只加 2 dp 外移，不做形变 |
| 竖版细长图 | 渲染只有约 20 dp 宽，几乎看不见 | 用接近 1:1 或 3.3:1 的构图 |
