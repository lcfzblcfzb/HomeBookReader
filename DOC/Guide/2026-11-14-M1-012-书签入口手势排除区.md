## 1. 问题与目标

Android 全屏沉浸（`immersiveSticky`）下，从屏幕上沿下滑会先由系统接管。书签入口贴在顶边，按住入口往下拖时手势常被系统抢走，入口拖不动，反而拉出状态栏/通知栏。

按确认的方案同时上 A、B 两层：

- **A**：把入口矩形通过 `setSystemGestureExclusionRects` 报给系统；
- **B**：让入口的触摸起点离开顶部手势带，并用入口自身盖住这段余量，视觉上不留缝。

不做「先长按再拖」的延迟方案。

## 2. A：Android 手势排除区

### 2.1 原生通道

`MainActivity.kt` 新增通道 `homepdfreader/gesture_exclusion`，与既有 `homepdfreader/storage_access` 并列：

| 方法 | 参数 | 行为 |
| --- | --- | --- |
| `setExclusionRects` | `rects: [{left, top, right, bottom}]`，单位 dp | 转 px、按屏幕边界裁剪后写入 `window.decorView.systemGestureExclusionRects` |
| `clearExclusionRects` | 无 | 写入空列表，清掉旧矩形 |

- `Build.VERSION.SDK_INT >= Q (29)` 才执行，低版本直接返回成功。
- 坐标使用 dp（Flutter 逻辑像素），Kotlin 侧乘 `displayMetrics.density` 转 px；`decorView` 在沉浸式下就是 Flutter 逻辑坐标的原点。

### 2.2 Dart 服务与预算裁剪

新增 [system_gesture_exclusion.dart](../../lib/core/platform/system_gesture_exclusion.dart) 与 `systemGestureExclusionProvider`：

- `isSupported` 用 `Platform.isAndroid`；Windows 等平台所有方法直接返回，不引入移动端依赖。
- `cropToBudget(rects, screenSize)`：先裁到屏幕内，再按系统限制裁剪——**上/下边看宽度、左/右边看高度，每条边合计最多 200 dp**，超出部分裁掉，避免「一次报满被系统整块裁掉」。
- 通道异常（`MissingPluginException` / `PlatformException`）只忽略，不影响阅读。

### 2.3 上报时机

`ReaderPage` 在入口可见后计算矩形并上报，矩形为入口当前可视矩形（宽 132 dp、高 `entryHeight + touchInset`）：

| 时机 | 处理 |
| --- | --- |
| 入口首次可见（位置记忆读完） | 首次上报 |
| 拖动结束、吸附落点更新 | 比例变化 → 矩形变化 → 重报 |
| 转屏 / 窗口尺寸变化 | 布局变化 → 矩形变化 → 重报 |
| 面板打开 / 关闭 | 强制重报一次（即使矩形相同） |
| 离开阅读页 | `clear()` 清空，不留旧矩形 |

相同矩形用 `_reportedExclusionRect` 去重，不会每帧走通道；上报放在 post-frame，避免在 build 中直接调平台。

## 3. B：顶部安全余量与视觉无缝

### 3.1 几何

`ReaderUiConfig.entryTopInset = 32`（24–32 可调；实测 Pixel 5 / API 30 顶部手势带约 30 dp，取 32 留余量）。

- 仅 Android（`isSupported`）生效；`BookmarkEntryLayout.touchInset` 携带该值。
- Android 上入口**不再折叠上移**，可视高度 = 40 + 32 = **72 dp**，从屏幕最上沿开始绘制，入口自身完整贴顶、盖住这段余量，视觉上没有缝隙。
- 入口下沿以下 40 dp 全部是可触摸区，其中 32 dp 以下落在应用自己的窗口里；自然握持点（入口中部）已经在系统手势带之外。
- Windows 分支 `touchInset = 0`，保持原来的折叠露出半截，行为与 M1-011 完全一致。
- 面板起点跟随入口可视下沿：`panelTopOffset` 之外再加 `touchInset`，面板仍从入口下沿滑入；`clampTop` 的上限也按 72 dp 计算，拖到底不会露出屏幕。

### 3.2 视觉

猫图按入口盒 `132 × 72` 用 `BoxFit.contain` 等比放大（正方形图 → 72×72），不再做染色或新图标；底部圆角与阴影随入口盒高度变化，三态缩放/旋转/阴影参数不变。

## 5. 验证

环境：`Pixel_5_API_30`（1080×2280，dpr 2.75），debug APK，`adb shell input swipe` + 截图 + logcat。

| 验证 | 方式 | 结果 |
| --- | --- | --- |
| 矩形上报 | logcat `GestureExclusion` | `Rect(519,0-882,198)`，与入口可视矩形一致 |
| 拖动结束 | 从入口中部斜滑 | 矩形变为 `Rect(0,0-363,198)` 并落库，入口跟手、松手吸附 |
| 转屏 | 竖屏 → 横屏 | 重报 `Rect(390,0-753,198)`，贴长边并按横屏记忆重锚定 |
| 面板打开 / 关闭 | 点击入口、返回键 | 矩形各强制重报一次，面板从入口下沿滑入 |
| 离开阅读页 | 返回书架 | `set rects=[]`，排除区清空 |
| 入口处下滑 | 从入口中部（36 dp）下滑 | 应用收到拖动，入口移动，未拉出通知栏 |
| 入口旁下滑 | 从排除矩形外下滑 | 正常拉出通知栏（证明排除区没有越界） |
| 系统顶部手势带 | 从入口顶部（< 30 dp）下滑 | 仍被系统接管，先拉出状态栏，入口按安全区下移 83 px |
| 单测 | `flutter test` | 53 条全部通过 |
| 静态检查 | `flutter analyze --no-pub` | 无 error / warning，仅既有 deprecated info |
| Windows 构建 | `flutter build windows` | 通过，无移动端依赖 |

### 5.1 关于 A 的实测结论

API 30 上 `setSystemGestureExclusionRects` **只对返回手势（左右边缘）生效，不改变通知栏下拉**：从入口顶部（仍在排除矩形内）起手下滑，系统依旧接管。矩形本身已正确上报并随位置/朝向更新，可在后续系统版本或其他 ROM 上继续观察；当前真正兜住拖动的是 B。

因此入口顶部约 30 dp 仍是系统手势带——这是「视觉贴顶 + 触摸下移」的必然取舍：若把入口整体再下移，就会在顶部露出可见缝隙。入口高 72 dp，中部（36 dp）与下部都在安全区内，正常握持拖动不会再被抢走。

## 6. 回归

- 三态（idle / dragging / active）与过渡：未改状态机，拖动缩放/倾斜、面板激活阴影正常。
- 拖动不翻页：入口命中区仍只有自身矩形，空区域透传给翻页层。
- 位置记忆：竖屏/横屏分别沿用，转屏重锚定正常。
- 沉浸式：进入阅读页隐藏系统栏，退出恢复；状态栏临时显示时入口按安全区下移。
- 面板从入口下沿滑入：面板起点跟随入口 72 dp 下沿。
