- 关联 TODO：[M1-书架与阅读骨架](../TODO/M1-书架与阅读骨架.md)

## 1. 改了什么

### 1.1 一键启动脚本（项目根目录）

- `run_windows.bat`：双击或终端执行；调用同目录 `run_windows.ps1`，失败时 `pause` 保留窗口。
- `run_windows.ps1`：
  - Flutter 路径按候选列表解析（`E:\flutter\bin\flutter.bat` 优先），**不依赖 PATH**；全部不存在时中文报错并退出 1。
  - 仅当环境变量为空时补 `PUB_CACHE=E:\pub-cache`、`PUB_HOSTED_URL`、`FLUTTER_STORAGE_BASE_URL`（国内镜像）。
  - `Set-Location` 到脚本所在目录后执行 `flutter run -d windows`。
  - 文件以 UTF-8 **带 BOM** 保存：PowerShell 5 会把无 BOM 的 UTF-8 当 GBK，中文注释会破坏语法（首次执行即踩到，已修正）。

### 1.2 阅读页首屏崩溃

- 现象：`flutter run -d windows` 启动即抛
  `StateError: Bad state: Cannot clone a disposed image`，
  报错位置 `reader_page.dart` 的 `FutureBuilder<Image?>` → `RawImage`。
- 原因：渲染图像由 `ReaderController` 缓存持有，窗口尺寸变化/控制器释放时会 `dispose()` 原图；而 `RawImage` 更新渲染对象时会对同一 `ui.Image` 调用 `clone()`，此时原图已被释放。
- 修复：`_PageImage` 不再直接用控制器返回的实例，而是
  1. 拿到缓存图后 `clone()` 一个自己持有的句柄；
  2. 用 `_requestId` 丢弃过期请求（快速翻页/改宽）；
  3. 在 `setState`/`dispose` 中释放自己持有的旧句柄；
  4. `clone()` 抛 `StateError` 时降级为「这一页渲染失败」，不再让整帧抛异常。

## 4. 风险与遗留

- 脚本只覆盖 Windows；Android 需要额外配置 NDK/cmdline-tools。
- 调试模式比较慢（Debug + Impeller OpenGL），发布版需 `flutter build windows --release`。
- 首屏进入阅读页的原始触发路径未复现清楚（路由无自动跳转），修复后启动与翻页均无异常；后续如再出现按同一日志定位。
- 界面视觉仍需人工确认（空书架 → 导入 → 阅读 → 书签）。
