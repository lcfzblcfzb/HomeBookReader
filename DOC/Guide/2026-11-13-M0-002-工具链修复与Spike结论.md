## 1. 改了什么

### 1.1 Windows C++ 构建链

- 现象：VS 2022 的 MSVC 目录只剩 `cl.exe`，`include/`、`lib/x64/` 为空，`vcvarsall.bat` 缺失；`pdfium_dart` 的 hooks（编译 `pdfrx_pdfium_gate`）与 Flutter Windows 构建全部阻断。
- 处理：
  1. 清理 `%TEMP%` 过期缓存（约 2.1GB）与 Windows 更新下载缓存；
  2. 将 VS 包缓存目录 `C:\ProgramData\Microsoft\VisualStudio\Packages` 以目录联接指向 `D:\VSPackages`，避开系统盘空间预检；
  3. `setup.exe install --productId Microsoft.VisualStudio.Product.BuildTools --channelId VisualStudio.17.Release --add Microsoft.VisualStudio.Workload.VCTools --includeRecommended --installPath D:\BuildTools --quiet --nocache`。
- 结果：`vswhere -requires Microsoft.VisualStudio.Component.VC.Tools.x86.x64` 返回 `D:\BuildTools`；`cl 19.44` 可编译，Flutter Windows 构建与 `flutter test` 恢复。

### 1.2 代码缺陷修复（单测暴露）

- [page_rect.dart](../../lib/core/geometry/page_rect.dart)：`fromLTRB` 先规范化再取 min/max；`_normalize` 对 `NaN` 归 0、`+∞` 归 1（原先 `+∞` 被归 0）。
- [selection_splitter.dart](../../lib/core/geometry/selection_splitter.dart)：`mergeLines` 改用「垂直重叠 > 较短矩形高度的一半」判断同行（原先用 `top - bottom` 的间隙，恒判为不同行）。

### 1.3 文本提取改为行级

- [pdfrx_engine.dart](../../lib/core/pdf/pdfrx_engine.dart)：`textLines` 不再直接映射 pdfrx 的 `fragments`（片段/词级，CJK 会被切成单字），改为利用「`fullText` 与 `charRects` 一一对应且已按 `\n` 分行」切行，输出真正的「行文本 + 字符范围 + 行矩形 + 字符矩形」。

### 1.4 应用标识统一

- Android：`namespace` / `applicationId` = `com.homepdfreader.app`，`MainActivity` 包名迁移，应用名 `HomePdfReader`。
- iOS：`PRODUCT_BUNDLE_IDENTIFIER` 同步为 `com.homepdfreader.app`。

## 2. 影响模块

| 模块 | 影响 |
| --- | --- |
| core/geometry | 归一化与同行合并语义修正，`PageRect` 不再接受非有限值导致的错误结果 |
| core/pdf | `textLines` 语义变为真正的行级，M5 划线的候选单位随之确定为「行 → 字符」 |
| app（平台配置） | 包名/应用名变更，安装到设备后会视为新应用 |
| 构建环境 | Windows 构建依赖 `D:\BuildTools`，不再依赖原 VS Community 的 C++ 组件 |

### Spike 结论

- **S1 渲染：可行。** Debug 构建下 800px 首帧 46–176ms，1600px 32–48ms，翻页 28–29ms；RSS ≈ 365–373MB。帧率未测（留 M2 Profile 验收）。
- **S2 文本：可行。** 每页 10 行、`charRects` 304（中文）/553（英文）；行文本、字符范围、行矩形、字符矩形齐全，中文提取正确（`第 1 页 / 共 10 页`）。**Gate 通过，无需替代方案。**
- **S3 目录：可行。** `sample_text_zh/en` 读到 4 节点、最大 2 层，`PdfDest.pageNumber` 1 基已转 0 基；`sample_no_outline` 与扫描件返回空列表。
- **S4 落库：可行且有坑。** 内存库插 1000 条约 204–246ms、查全部 22ms、进度读写正常；应用真实落盘路径（`driftDatabase`）未在本项覆盖，留应用启动验证。

## 4. 风险与遗留

- material 弃用提示 11 条，需统一迁移 `material_ui`（不影响功能）。
- 扫描件 `hasTextLayer=false` 已能识别，UI 降级提示留 M5。
- S1 内存为 Debug 数值，Release 基线留 M2。
- Android 构建需 NDK/cmdline-tools，本轮未验证。
