## 1. 改了什么

| 文件 | 变更 |
| --- | --- |
| `lib/core/utils/app_logger.dart`（新增） | 全局日志 + 未处理异常捕获，追加写 `HPR_LOG_FILE` 指定文件 |
| `lib/main.dart` | `runZonedGuarded` 包裹启动流程，启动期异常也落盘 |
| `run_windows.ps1` | `flutter run` 的 stdout/stderr 双写按次日志与 `latest.log`；传递 `HPR_LOG_FILE` |
| `.gitignore` | 新增 `/logs/` |

### 1.1 文件布局

```
logs\
  run-20261113-110848.log   # 按次归档：启动器信息 + 构建/运行全部输出 + 退出码
  latest.log                # 最近一次运行；内容与对应 run-*.log 相同，应用内日志也追加到这里
```

- `run_windows.ps1` 启动时创建 `logs\`，本次日志名取 `run-<yyyyMMdd-HHmmss>.log`，`latest.log` 每次运行重建。
- 通过环境变量 `HPR_LOG_FILE` 把 `latest.log` 绝对路径传给应用；应用不需要知道脚本实现。
- 应用直接运行（不经脚本）时 `HPR_LOG_FILE` 为空，退回到应用私有目录的 `logs\app.log`，仍有留痕。

### 1.2 日志里有什么

- 启动器头 4 行：启动时间、实际使用的 Flutter 路径、项目目录、本次日志路径。
- `flutter run` 全部输出：镜像提示、构建耗时、启动、VM Service 地址。
- 应用行格式：`[yyyy-MM-dd HH:mm:ss.SSS] [LEVEL] [TAG] 消息 | 补充`，异常另起 `error:` 与堆栈。

| TAG | 来源 |
| --- | --- |
| `BOOT` | 启动完成、启动期异常（`runZonedGuarded`） |
| `FRAME` | 框架异常（`FlutterError.onError`，含 widget 构建/布局/绘制） |
| `ASYNC` | 未捕获异步异常（`PlatformDispatcher.onError`） |
| `APP` | 业务主动调用 `AppLogger.log(...)` |

- 应用内日志同时写文件与 `debugPrint`；当 `HPR_LOG_FILE` 已设置（脚本已捕获 stdout）时只写文件，避免同一行出现两次。

## 2. 怎么读

在项目根目录执行（PowerShell）：

```powershell
# 最近一次运行的最后 60 行
Get-Content logs\latest.log -Tail 60

# 只看错误
Select-String -Path logs\latest.log -Pattern '\[ERROR\]'

# 实时跟随
Get-Content logs\latest.log -Wait -Tail 20

# 历史某次运行
Get-Content logs\run-20261113-110848.log
```

- 文件以 UTF-8 **BOM** 开头，PowerShell 5 的 `Get-Content` 能正确显示中文。
- 命令行里用 `h` 可看到 `flutter run` 的交互键；日志文件不会记录这些按键，只记录输出。

## 5. 已知坑与注意

- **PowerShell 5 编码**：`.ps1` 必须 UTF-8 带 BOM，否则中文注释按 GBK 解析会导致语法错误；日志文件同理需要 BOM 才能正确读中文。
- **`$ErrorActionPreference='Stop'`**：`flutter` 会向 stderr 写提示，Stop 模式下会被当成终止性错误导致脚本提前退出、丢失输出。调用段临时设为 `Continue` 后再恢复。
- **异常不会让应用退出**：`PlatformDispatcher.onError` 返回 `true`，界面异常只留痕；排查时以 `[ERROR]` 行为起点，向上看时间戳前后文。
- **日志会持续增长**：`latest.log` 每次运行重建，不会无限追加；`run-*.log` 按次累积，需要时手动清理 `logs\`。
