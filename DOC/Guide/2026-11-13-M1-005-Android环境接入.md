## 1. 环境结论

沿用本机 `D:\AndroidSDK`，未重新下载 SDK、未迁移目录。Flutter 3.50 / AGP 9.3.1 / Gradle 9.5 要求与补齐情况：

| 要求 | 原状态 | 处理 |
| --- | --- | --- |
| JDK 17+ | `JAVA_HOME=D:\JDK17\jdk-17.0.12`（PATH 上的 `java` 是 1.8，Gradle 不看它） | 无需安装，脚本显式设置 `JAVA_HOME` |
| SDK Platform 36（compileSdk/targetSdk） | 已有 android-33/34/36 | 无需补 |
| SDK Platform 35 | 缺失（插件 `jni` 的 compileSdk=35） | 补 `platforms/android-35` |
| build-tools 36 | 最高 34.0.0 | 补 `build-tools/36.0.0` |
| NDK 28.2.13676358 | 完全缺失 | 补 `ndk/28.2.13676358`（约 2.1 GB） |
| CMake 3.22.1 | 缺失（插件 `jni` 用 CMake 构建） | 补 `cmake/3.22.1` |
| cmdline-tools | 只有旧 `tools\bin\sdkmanager`，JDK 17 下报 `javax/xml/bind` | 官方 `commandlinetools-win-16111833` → `cmdline-tools\latest` |
| licenses | 已有 license 文件，但无法校验 | `sdkmanager --licenses` 确认；`flutter doctor` Android toolchain 通过 |
| 模拟器 | emulator 36.3.10 + AVD `Pixel_5_API_30`（Android 11 / x86_64） | 直接可用，WHPX 可用 |

版本发现方式：`FlutterExtension.kt` 中 `compileSdkVersion=36`、`minSdkVersion=24`、`ndkVersion=28.2.13676358`；项目 `settings.gradle.kts` 使用 AGP 9.3.1、Kotlin 2.4.20、Gradle 9.5。

## 2. 环境冲突与处理（不静默换位置）

| 冲突 | 现象 | 决定 |
| --- | --- | --- |
| 全局 `~/.gradle/init.gradle` 给所有项目注入项目级 maven 仓库 | Gradle 9 下解析 `dev.flutter.flutter-plugin-loader` 直接失败：`Build was configured to prefer settings repositories over project repositories` | **保留 SDK 位置**，改 init 脚本：`gradle.parent != null`（included build）时跳过注入 |
| Gradle 官方发行包 | `services.gradle.org` 307 到 GitHub Releases，本机 0 字节卡死 | wrapper `distributionUrl` 改腾讯镜像，并用 curl 手动下载 240 MB 装入 wrapper 缓存（镜像对 Java 下载器返回反爬页） |
| C: 盘空间 | 构建时 `There is not enough space on the disk`（C: 0 GB） | `~/.gradle`（1.69 GB）迁到 `E:\gradle-home`，原路径建 Junction；SDK 位置不动 |
| Kotlin 增量缓存 | `:android_file_picker:compileDebugKotlin` 报 `Could not close incremental caches` | `android/gradle.properties` 加 `kotlin.incremental=false` |
| 插件 `jni` 的平台 | 缺 `platforms;android-35` 时任务配置失败 | 补 android-35，不改插件代码 |

> 说明：`init.gradle` 与 Gradle 缓存都在用户目录，不属于仓库内容，但换机器/重装系统后需按本节重现。

## 3. Android 启动方式

### 3.1 一键脚本（推荐）

```powershell
cd d:\ToolProjects\HomePdfReader
.\run_android.bat              # 自动使用唯一已连接设备
.\run_android.bat emulator-5554   # 指定设备
```

`run_android.ps1` 做了这些事：固定 Flutter 路径（`E:\flutter\bin\flutter.bat`，不依赖 PATH）、设置 `JAVA_HOME` / `ANDROID_HOME` / pub 镜像、把 `platform-tools` 加进 PATH、用 `adb devices` 选中唯一在线设备、再执行 `flutter run -d <id>`。

### 3.2 手动命令

```powershell
cd d:\ToolProjects\HomePdfReader
$env:JAVA_HOME='D:\JDK17\jdk-17.0.12'
$env:ANDROID_HOME='D:\AndroidSDK'
$env:ANDROID_SDK_ROOT='D:\AndroidSDK'
E:\flutter\bin\flutter.bat devices          # 查设备 id
E:\flutter\bin\flutter.bat run -d emulator-5554
```

### 3.3 设备 id 怎么查

| 用途 | 命令 | 说明 |
| --- | --- | --- |
| Flutter 视角 | `flutter devices` | 输出 `emulator-5554`、真机序列号等 |
| adb 视角 | `D:\AndroidSDK\platform-tools\adb.exe devices` | `device` 表示在线，`offline/unauthorized` 需处理 |
| 多设备时指定 | `flutter run -d <id>` | 也可用 `adb -s <id> shell ...` |

### 3.4 启动模拟器

```powershell
& 'D:\AndroidSDK\emulator\emulator.exe' -avd Pixel_5_API_30
```

真机：开启开发者选项与 USB 调试，`adb devices` 看到 `device` 即可用同一脚本启动。

### 3.5 Android 应用日志

- 启动脚本不写 `logs\`；Android 上的应用日志写入应用私有目录：`/data/user/0/com.homepdfreader.app/files/logs/app.log`（debug 包可用 `run-as` 读取）。
- 实时看：

```powershell
D:\AndroidSDK\platform-tools\adb.exe logcat -s flutter
D:\AndroidSDK\platform-tools\adb.exe shell run-as com.homepdfreader.app cat files/logs/app.log
```

## 6. 已知问题

- 模拟器 API 30 + Impeller GLES 会打印 `EGL Error: Success` 与跳帧日志，属渲染后端提示，不影响使用。
- 首次构建会下载 AGP/Kotlin/PDFium 依赖，耗时较长；PDFium 从 GitHub 下载偶发超时，会自动重试。
- 若网络可直连 Google/GitHub，可把 wrapper 的 `distributionUrl` 改回官方地址。
