# M1-010 书签入口位置与拖拽吸附 TODO

> 依据：[开发大纲](../开发大纲.md) M1 阅读体验打磨
> 状态：进行中
> 范围：只改阅读页顶部书签入口的定位与手势；不新增常驻控件、不改面板内容

## 1. 目标

1. 入口初始位置从屏幕顶部居中改到**右上角**，折叠露出比例保持 50%。
2. 按住入口可**自由拖动**（跟手），松手后平滑吸附回当前朝向的**上侧边**：只沿顶边滑动到松手点横坐标。
3. 「上侧」跟随屏幕朝向：竖屏短边在上、横屏长边在上；旋转后重新贴回新顶边，不会留在旧边或跑到侧面。
4. 位置记忆：竖屏、横屏分别持久化横坐标，互不覆盖；下次进入阅读页沿用。
5. 吸附/回弹有过渡动画；吸附后仍可点开面板，面板仍从入口下沿滑入。
6. 兼容现有翻页点击区、沉浸式系统栏、安全区（打孔/刘海）：拖动不被系统状态栏触摸带吃掉，入口不被裁剪。

## 2. 方案

### 2.1 坐标与布局

- 新增 `BookmarkEntryLayout`（阅读页 Stack 坐标系）：可用横坐标范围 `[minLeft, maxLeft]`、顶边 `top`、纵向可拖动上限 `maxTop`。
- 安全区取 `MediaQuery.padding`：沉浸式下系统栏 inset 为 0（入口仍贴屏幕物理上沿）；打孔/刘海保留的 inset 会参与 clamp，避免被裁。
- 初始值 = `maxLeft`（右上角）；横坐标以 **0..1 比例** 落库，窗口宽度变化后仍能还原到相同相对位置。

### 2.2 拖动与吸附

- `BookmarkEntry` 内部持有：静止横坐标 `_restLeft`、拖动实时位置、吸附动画（`AnimationController` + `Offset.lerp`）。
- 指针按下：记录起点、展开入口；移动超过 `kTouchSlop` 进入拖动，位置跟随手指并 clamp 在屏幕内。
- 抬手：若拖动过，横坐标取松手点（clamp 后）作为新落点，纵向平滑吸附到 `layout.top`，完成后回弹折叠；若没拖动，沿用原逻辑（在入口内则打开面板）。
- 根节点改为铺满阅读区的 `Stack`（只放一个 `Positioned` 入口），空区域不参与命中，不影响左右翻页点击区。
- 旋转/窗口尺寸变化：`didUpdateWidget` 检测 `layout` 变化，取消拖动与吸附，按新朝向记住的比例重新贴顶；同朝向仅尺寸变化时按比例保持。

### 2.3 持久化

- 新增 `ReaderEntryPositionRepository`，复用 `app_meta` 表：
  - `reader.entry_x.portrait`
  - `reader.entry_x.landscape`
- value 为 0..1 的横坐标比例；写入用 `insertOnConflictUpdate`，读取失败/为空时回退右上角。
- 阅读页在文档可用前读取两个朝向的值，读完再展示入口，避免首帧位置跳变。

### 2.4 面板与入口的关系

- 面板 `top` 改为 `layout.top + ReaderUiConfig.entryHeight`，始终从入口下沿滑入。
- 入口仍在浮层之后绘制，面板打开时不被遮罩压暗。

## 5. 风险与注意

- Android 状态栏触摸带：保持沉浸式（`immersiveSticky`）；入口按下后由自身 Listener 持有手势，避免被系统栏截走。
- 面板打开时拖动入口：允许拖动，但松手不折叠；面板 top 固定，不跟随横坐标。
- 位置比例落库需在吸附开始时写入，避免动画中途退出丢位置。
