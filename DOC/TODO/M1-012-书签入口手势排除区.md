# M1-012 书签入口手势排除区 TODO

> 依据：[开发大纲](../开发大纲.md) M1 阅读体验打磨
> 状态：已完成（A 已上报；API 30 上 A 不覆盖通知栏下拉，B 兜底）
> 范围：只处理「书签入口 ↔ Android 顶部下拉通知栏」手势冲突；不做长按延迟方案

## 1. 问题

Android 全屏沉浸（`immersiveSticky`）下，从屏幕上沿下滑会先由系统接管：轻则拉出状态栏，重则展开通知栏。
书签入口贴在顶边，用户按住入口往下拖时，手势常被系统抢走，入口拖不动反而拉出通知栏。

用户已确认同时上 A、B 两种手段：

- A. 手势排除区：把入口当前矩形通过 `setSystemGestureExclusionRects` 报给系统；
- B. 吸附位置离顶留安全余量：入口的触摸起点默认离顶 24–32 dp（配置项可调），兜底不遵守排除区的 ROM。

## 2. 方案

### 2.1 A：Android 手势排除区

平台层（`MainActivity.kt`）新增通道 `homepdfreader/gesture_exclusion`：

| 方法 | 参数 | 说明 |
| --- | --- | --- |
| `setExclusionRects` | `rects`: `[{left, top, right, bottom}]`，单位 dp | 转 px 后调用 `window.decorView.systemGestureExclusionRects` |
| `clearExclusionRects` | 无 | 清空，离开阅读页时调用 |

- 仅 `Build.VERSION.SDK_INT >= Q (29)` 生效；低版本静默跳过。
- 系统限制：每条边合计最多 **200 dp**，超出会被裁剪。Dart 侧先按屏幕边界与 200 dp 预算裁剪再上报，Kotlin 侧再按屏幕边界兜底，避免「一次报满导致失效」。

Dart 侧（`lib/core/platform/system_gesture_exclusion.dart`）：

- `isSupported`：`Platform.isAndroid`；Windows 直接跳过，不引入移动端依赖。
- `cropToBudget(rects, screenSize)`：纯函数，可单测。先裁到屏幕内，再按「上/下边看宽度、左/右边看高度」逐条扣 200 dp 预算。
- `setRects` / `clear`：通道调用，异常只记录不崩溃。

上报时机（`ReaderPage`）：

- 入口首次可见（读完位置记忆后）；
- 吸附落点变化（拖动结束、位置记忆更新）；
- 转屏 / 窗口尺寸变化导致布局变化；
- 面板打开 / 关闭（强制重报一次）；
- 离开阅读页清空，不留旧矩形。

### 2.2 B：吸附位置离顶安全余量

- `ReaderUiConfig.entryTopInset = 28`（24–32 可调）。
- 仅 Android（`isSupported`）启用：入口不再上移折叠露出半截，而是完整贴在顶边，整个入口自身就是「覆盖余量的露出部分」，视觉无缝隙。
- 入口可触摸区域因此延伸到顶边下 40 dp，其中 28 dp 以下的部分落在应用自己的窗口里，不依赖排除区也能拖动。
- Windows 保持原折叠露出行为（`entryTopInset` 不生效）。
- 面板仍从入口下沿（`panelTopOffset = entryHeight`）滑入，面板/遮罩逻辑不变。

### 2.3 不破坏既有行为

- 三态过渡、拖动不翻页、竖屏/横屏位置记忆、转屏重锚定、沉浸式、面板从入口下沿滑入。
- 入口仍只命中自身矩形；空区域透传给翻页层。
